# Промт для Claude: разработка ПЛК-программы (дублирующее зажигание + телеметрия ГАЗ-2410)

Готовый промт ниже можно скопировать целиком в новый диалог с Claude, чтобы
получить программу ПЛК (IEC 61131-3 / OpenPLC) для управления дублирующей
системой зажигания и опроса телеметрии по Modbus RTU.

---

## ПРОМТ (скопировать целиком)

Ты — инженер по промышленной автоматизации. Нужно разработать программу
ПЛК на языке Structured Text (IEC 61131-3), совместимую с рантаймом
**OpenPLC** (работает на Raspberry Pi рядом с BlueOS, поддерживает
Modbus RTU master «из коробки»), для управления двумя подсистемами
автомобиля ГАЗ-2410 (двигатель ЗМЗ-402):

1. **Дублирующая система зажигания** — переключение между штатным
   трамблёром и МПСЗ (микропроцессорной системой зажигания) с защитой
   от одновременного включения обоих контуров.
2. **Телеметрия по RS-485 (Modbus RTU)** — опрос узлов на ESP32
   (датчики температуры, тока, напряжения) и генерация аварийных
   сигналов при выходе параметров за пределы.

### Список устройств (физический слой)

**Контур зажигания:**
- Блок МПСЗ-4 (4-канальный, формирует УОЗ по картам «Эко»/«Спорт»)
- ДПКВ (индуктивный датчик, диск 60-2, 58 зубьев + пропуск)
- Коммутаторы зажигания — 2 шт.
- Катушки зажигания сдвоенные — 2 шт.
- Штатный трамблёр + штатная катушка Б117А
- Силовой тумблер ТВ1-2 (управляет обмоткой реле, не силовой цепью)
- Силовое реле 12В/30–40А — отдельно для контура «Трамблёр» и контура «МПСЗ»
- Датчик детонации (резьба М8, аналоговый/широкополосный)

**Контур телеметрии:**
- Узлы ESP32 (Modbus RTU slave, адреса 1..N) с датчиками:
  - DS18B20 — температура ГБЦ, АКБ, радиатор (вход/выход)
  - ACS712-30A — ток генератора/потребителей
  - Делитель напряжения 10 кОм/33 кОм — напряжение борт. сети 12–14В
  - АЦП ADS1115 на каждом узле
- Трансивер MAX485 на каждом узле и на мастере (ПЛК/шлюз)
- Шина RS-485: экранированная витая пара кат. 5e/6, терминаторы 120 Ом
  на обоих концах

### Карта входов/выходов ПЛК

| Тип | Тег | Устройство | Описание |
|---|---|---|---|
| DI | `SW_MODE` | Тумблер ТВ1-2 | 0 = Трамблёр (штатный), 1 = МПСЗ |
| DI | `MPSZ_HEALTHY` | Диагностический выход МПСЗ | 1 = МПСЗ исправна, 0 = отказ электроники |
| AI | `KNOCK_LEVEL` | Датчик детонации | Уровень сигнала детонации (0–100%) |
| DO | `RELAY_TRAMBLER` | Силовое реле контура «Трамблёр» | Включение штатного контура |
| DO | `RELAY_MPSZ` | Силовое реле контура «МПСЗ» | Включение контура МПСЗ |
| DO | `ALARM_KNOCK` | Индикатор/зуммер | Сигнал превышения порога детонации |
| Modbus (holding regs, RTU master) | `TEMP[1..N]` | DS18B20 через ESP32-узлы | Температура по точкам, °C ×10 |
| Modbus (holding regs) | `CURRENT[1..N]` | ACS712 через ESP32-узлы | Ток, А ×100 |
| Modbus (holding regs) | `VOLTAGE` | Делитель напряжения через ESP32 | Напряжение борт. сети, В ×100 |

### Требуемая логика программы

1. **Интерлок контуров зажигания (главный приоритет — безопасность):**
   - `RELAY_TRAMBLER` и `RELAY_MPSZ` не могут быть включены одновременно
     ни при каких условиях (программный и, если возможно на используемом
     железе, аппаратный интерлок).
   - Если `SW_MODE = 1` (МПСЗ) и `MPSZ_HEALTHY = 0` (отказ электроники) —
     принудительно включить `RELAY_TRAMBLER`, `RELAY_MPSZ` выключить,
     независимо от положения тумблера (автоматический fallback на
     механический контур).
   - Переключение реле — с антидребезгом (debounce) по `SW_MODE`, не
     менее 200 мс задержки перед переключением.

2. **Защита от детонации:**
   - Если `KNOCK_LEVEL` превышает пороговое значение (константа,
     настраиваемая) дольше заданного времени — включить `ALARM_KNOCK`.
   - Предусмотреть гистерезис, чтобы избежать дребезга аварии на
     границе порога.

3. **Опрос телеметрии (Modbus RTU master):**
   - Циклический опрос всех slave-узлов ESP32 по адресам 1..N с
     таймаутом и счётчиком ошибок связи на узел.
   - При потере связи с узлом дольше N секунд — пометить его данные
     как «stale» (не использовать в логике аварий) и включить
     диагностический флаг.
   - Полученные значения температуры/тока/напряжения передавать далее
     в BlueOS (через существующий Modbus→MQTT шлюз в Docker-контейнере,
     `pymodbus` на стороне BlueOS уже реализован отдельно — со стороны
     ПЛК просто выступать Modbus RTU slave или держать данные в
     holding-регистрах, доступных внешнему мастеру/шлюзу).
   - Аварийные пороги: перегрев (порог по каждой точке измерения),
     недозаряд/перезаряд по напряжению борт. сети, превышение тока.

4. **Общие требования к коду:**
   - Структурированный текст (ST), разбитый на понятные функциональные
     блоки (FB_IgnitionInterlock, FB_KnockProtection, FB_ModbusPoll,
     FB_AlarmThresholds).
   - Все пороги и тайминги — именованные константы в начале программы,
     не «магические числа» внутри логики.
   - Комментарии — только там, где логика неочевидна (например, почему
     нужен антидребезг или почему интерлок реализован именно так).
   - Не добавлять функциональность сверх описанной (без веб-интерфейса,
     без отдельного отображения — это делает BlueOS).

### Формат ответа

Выдай:
1. Итоговую программу на Structured Text, готовую к импорту в OpenPLC
   Editor (с описанием переменных в начале файла).
2. Краткое пояснение сделанных допущений (пороги детонации, тайминги
   антидребезга, число N узлов телеметрии) — если что-то не указано
   явно, выбери разумное значение и явно пометь его как допущение,
   которое нужно откалибровать на реальном автомобиле.

## Как использовать

1. Скопируйте блок между `## ПРОМТ` и `## Как использовать` в новый чат.
2. При необходимости отредактируйте число узлов телеметрии `N`, конкретные
   пороги детонации/температуры — если они уже известны из технических
   характеристик датчиков.
3. Получив программу, сохраните её в `plc/ignition_telemetry.st` в этом
   репозитории и протестируйте на OpenPLC Runtime (симулятор или Raspberry Pi).
